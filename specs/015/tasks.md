# 015 - Tasks

- [x] 1. Add safe stage-aware OpenRouter diagnostics. Define a typed stage/event contract and allowlisted cause extraction for prompt safety, query embeddings, answer generation, and answer streaming. Record only configured model, elapsed time, safe status/code, and retry details that are actually known. **Ready when:** each failure can be attributed to its operation stage without logging prompt/evidence contents, credentials, headers, raw messages, or response bodies. **Dependencies:** none.
- [x] 2. Instrument the question pipeline and runtime. Inject the diagnostic logger through `createAskService()` and wrap safety, embedding, and answer calls in both buffered and streaming paths; exclude cancellation and local validation/retrieval failures from provider-failure events. Keep service startup free of OpenRouter calls. **Ready when:** the runtime logger is injectable, each provider call is wrapped with its stage, and startup performs zero inference requests. **Dependencies:** 1.
- [x] 3. Classify streaming retryability by failure type. Replace the current rule that treats every non-guardrail stream failure as retryable with an explicit transient-failure classification shared by provider/network error handling. Do not retry authentication, invalid request/model, billing/credit, guardrail, validation, or local database errors. **Ready when:** only bounded transient failures request a frontend retry and user-facing stream messages remain generic. **Dependencies:** 1.
- [ ] 4. Add diagnostic and retry regression coverage. Test nested provider causes and redaction; inject failures in each provider stage; verify elapsed time, stage/model/status/code fields, cancellation behavior, retryable versus non-retryable classes, and no-startup-call behavior. **Ready when:** tests cover AC-1 through AC-4 and AC-7 without live OpenRouter calls or real credentials. **Dependencies:** 1, 2, 3.
- [ ] 5. Reproduce and classify the first-request failure using the new diagnostics. Compare the first and subsequent requests by stage, safe status/code, and duration; record the likely cause or explicitly note that available evidence does not isolate one. **Ready when:** AC-5 is met and the findings are documented without sensitive request or provider payload data. **Dependencies:** 2, 4.
- [ ] 6. Decide whether to start a separate warmup activity. If evidence confirms an inference cold start and a real model call is likely to help, write a follow-up spec/plan for opt-in warmup covering exercised stages, fixed synthetic input, timeout, cost, and startup-failure policy. Otherwise document why diagnostics or the confirmed non-cold-start fix address the issue. **Ready when:** a warmup decision is reviewable and AC-6 is either addressed by a follow-up proposal or explicitly determined unnecessary. **Dependencies:** 5.
- [ ] 7. Review the integrated diagnostic change. Confirm failure stage attribution, safe logs, retry bounds, unchanged answer/API behavior, and no unintended OpenRouter inference at startup. **Ready when:** RF-1 through RF-7 and AC-1 through AC-7 are satisfied and the relevant project checks pass. **Dependencies:** 1, 2, 3, 4, 5, 6.
